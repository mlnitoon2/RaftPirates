# Raft scale and shop swipe audit

The original ARMv7 binary has `GridSprite::UpdatePiece` at `0x5cd608`: it obtains the piece world position and calls `OceanView::ConvertToViewSpecial` (`0x4706a4`) before adding the asset offset. The unscaled projection there is `(192*(x-y),96*(x+y))`. The original `OceanView::Init` calls `SetUnitSize(430)` and selects a 0.7 or 0.5 camera zoom. Those are native view-space values, not directly interchangeable with the software renderer's logical pixels. Original wood/core PNGs are 384x216. This pass halves the reconstruction's projected hull and matching axes from 192x108 to 96x54 at default zoom, retaining component art scale and server footprint coordinates. This is a visual calibration requested for the reconstructed client, not a claim that 48 is the native unit constant.

`MenuSwipeComponent::gotMsgTouchDrag` at `0x7752f0` updates scroll offset while dragging and uses a four-unit threshold. The original `tabbed_menu_blueprints.xml` sets five visible slots, `direction=0`, `mode=1`, and scroll extent `itemWidth*(numItems-5)`. The reconstruction now keeps five visible slots and one look-ahead node, recycles those nodes as the user drags across cells, and avoids recreating the entire menu on page changes. The global offset is clamped to the original extent. Other store list drags use the existing swiper offset. The shop backdrop is redrawn at most five times per second while the menu remains interactive. Full native inertial scrolling, device benchmarking and exact native renderer equivalence remain unverified.
